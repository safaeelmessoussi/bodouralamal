# Bodour Al Amal — agent guide

React/Vite (RTL Arabic) · Express/Prisma 7 · PostgreSQL 18 · S3 (SeaweedFS/MinIO) · pg-boss · self-hosted LiveKit. `AGENTS.md` points here. Neither overrides `docs/SRS.md`.

## Start of session
1. `git status`, HEAD, full in-progress diff — preserve inherited work.
2. Read `docs/TASKS.md` (open items only) and `tail -n 60 docs/CHANGES.log`.
3. Read SRS §20 once, then only the clauses the task touches. **SRS is immutable to agents**: if it is wrong, silent or contradictory, stop that part and ask the Owner the smallest question. Never choose product policy.
4. Before code: [engineering constitution](docs/development/engineering-constitution.md); for UI: [UX rules](docs/development/ux-architecture.md) + [`design.mmd`](design.mmd). Once per session: [efficiency](docs/development/engineering-efficiency.md), [documentation policy](docs/development/documentation-policy.md).
5. Do not load `docs/archive/` unless the task cites it.

## Hard rules
- No destructive git, no history rewrite/force push, never touch `baseline/pre-codex-r100`; commit/push only when asked, on `develop`.
- No Production/Staging/DNS/secrets/data mutation without Owner authorization; **Production go-live is on hold**. Never reset/reseed Owner-populated Localhost or Staging to make tests pass.
- Media and recordings stay on the Morocco-hosted stack (no LiveKit Cloud, AWS, GCP, Azure). Never commit secrets, prices, contacts; never log PII or bodies.
- HTTP in controllers, transactions in services, data access in repositories; server owns authorization, visibility, Hijri, display identity. TD-3.8 error envelope; TD-3 ↔ OpenAPI ↔ code in sync. Never `prisma db push`. Don't remove a check because another layer looks similar.
- UI: keep DOM/class names (tests and harnesses pin them); CSS through semantic tokens only (`check-design-tokens.sh`); the Arabic catalogue is the Owner's (R71 guard).
- Verified = ran clean this session (exit 0, seen). Integration after any service rule change; seed drill before pushing anything that touches seeds/materialisation.

## Done = code + docs in one commit
Update affected handbook pages (facts only, cite the SRS, no history), `docs/TASKS.md` (tick = delete row), append ≤6 lines to `docs/CHANGES.log`; `bash scripts/ci/check-doc-links.sh && git diff --check`. Report in six sections: **user-visible · engineering · docs · defects found · verification (name skipped checks) · remaining**. Start anything written for the Owner with «Written for: …».
